# Project guidelines

Follow `../right-answers/README.md`, `../right-answers/swift.md`, and
`../right-answers/ci.md` for shared conventions.

Use `make build`, `make test`, `make coverage`, `make lint`, and `make fmt`.
`project.yml` is the source of truth for the generated Xcode project and app
metadata. The Swift package owns the font engine and its tests.

Preserve calibrated links, independent typography, native-unit metrics, and
fixed-baseline glyph navigation when changing the app. Missing fonts or
characters must be visible; never compare a silent fallback.

The app is being rebuilt to `docs/redesign/spec.md`, which the owner approved;
`docs/redesign/mockups/` shows every state. Where the spec and the app disagree
on layout, controls, or wording, build to the spec. Its Decisions section marks
what the owner decided; ask before departing from a decided item.

The fuzzer finds controls by accessibility identifier, title, description, and
help, and recorded traces replay the names they saw. Identifiers for per-font
controls are its contract: `Font A <label>` or `Font B <label>` built with
`side.fontName`, and scroll areas ending in `scroll area`. An identifier must be
unique within a window and never equal another element's label, title, or menu
title. Changing an identifier, label, or title the fuzzer uses, such as
`Font A Size field`, `Font B Inspector Size field`,
`Comparison inspector scroll area`, `Glyph canvas`, `Find Character`,
`Search Languages`, `Open typography inspector`, the `Font A specimen` labels,
`Search characters`, `Zoom in`, `Zoom out`, `Reset glyph zoom`, and the
symbol-name identifiers of icon-only buttons, breaks every recorded trace that
replays it. Change one only when the design calls for it, regenerate the
affected traces in the same change, and keep this paragraph naming the controls
in use. The redesign replaces many of these names, and the owner has accepted
losing the traces recorded before it. Match mode's `Cancel matching` button and
the editor sheet's `Custom specimen text` field also tell the fuzzer which
operation is active, so a recorded action can require it. Name matching, window
scope, and visibility rules live in `Sources/UIFuzzSupport` behind
`AccessibilityNode`, where the coverage gate applies. `Sources/UIFuzz` adapts
the system accessibility API to them, and its `AXDiscovery.swift` still decides
which actions each control offers, outside the gate.

Character search uses the running macOS's Unicode names, which differ between
macOS versions, and CI tests on macOS 15, 26, and 27. Tests that depend on names
must use long-established characters.

`Sources/TypefaceCore/Resources/character-frequencies.tsv` is generated by
`make frequencies`; change `scripts/character-frequencies.swift`, never the
table.

`make coverage` requires 100% line and region coverage for every gated source
file. Exit tests must enable LLVM continuous profiling (`%c` in the inherited
`LLVM_PROFILE_FILE`) before spawning their child so crashes preserve counters.
Keep fail-fast checks concise with `precondition(condition)` or `try!`. Coverage
counts the closing line of a `while true` loop, which has no reachable exit, so
loop on a condition.

Cover optional font metadata with synthetic fixtures. Coverage must not depend
on user-installed fonts or incidental view teardown. Counts clamped by
`llvm-cov`'s JSON exporter are invalid coverage measurements and fail the gate.
